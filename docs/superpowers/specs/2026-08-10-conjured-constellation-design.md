# Conjured Constellation — home page daily card showcase

**Date:** 2026-08-10
**Status:** Design approved, ready for implementation plan
**Area:** `app/web` — home page (`src/app/[locale]/page.tsx`)

## Summary

Add a daily-rotating showcase of real cards to the foot of the home page,
inspired by Scryfall's fanned row of random cards. Revelio's take — the
**Conjured Constellation** — casts a fresh set of cards from a wand-spark on
page load (echoing the logo's wand-and-spark mark), then lets them settle into
a gently drifting arc over the existing star-field. The set rotates once every
24 hours and is deterministic, so every visitor sees the same cards for the day.

## Goals

- A distinctive, on-brand home-page flourish that surfaces real cards from the
  database and invites exploration.
- Deterministic daily rotation, stable for all visitors within a UTC day,
  matching the existing `pickDailyExamples` behaviour.
- Zero layout interference with the search-first hero: the showcase lives in its
  own band pinned to the bottom, fully below the search box, example chips, and
  recent-sets list.
- Accessible and motion-safe by default.

## Non-goals

- No connecting "spell-lines" between cards (considered and cut as clutter).
- No new image pipeline — reuse existing card images and `CardImage`.
- No client-side data fetching — the daily set is resolved on the server.

## User-facing behaviour

**On load (the cast, ~1s, once):**

1. A gold wand-spark flares at the base of the band.
2. Cards burst outward from the spark, staggered, and fan up into the band.
3. Cards settle into a composed arc that crests in the middle.

**At rest:** cards bob slowly (subtle vertical drift, staggered per card); the
star-field twinkles. No connecting lines.

**Interaction:** hovering or keyboard-focusing a card lifts it and reveals it in
a soft gold glow. Clicking navigates to that card's detail page.

**Reduced motion:** with `prefers-reduced-motion: reduce`, cards render
pre-settled in their arc — no cast animation, no drift, static stars.

## Layout & composition

- The showcase is a compact band pinned to the bottom of the hero, roughly
  160–170px tall on desktop, entirely below the search UI. Cards never enter the
  search zone.
- **Desktop:** 6 cards. **Mobile / narrow:** 4 cards, a tighter fan, larger
  faces for thumb reach.
- Cards are scattered organically — an even-ish horizontal spread with varied
  height and tilt so the arrangement reads natural, not a rigid fan. Each card
  is given a horizontal cell across the band, then jittered within that cell
  (position, vertical offset, and rotation) so cards cover the width without
  overlapping while still looking hand-strewn.
- Positions are generated by the **same daily seed** via `mulberry32(dayNumber)`,
  so the scatter varies day to day yet stays deterministic (SSR matches client)
  and is guaranteed collision-free by the per-cell approach. Reference values
  for one day (`[leftPct, topPct within band, rotDeg]`), as illustration:
  - Desktop: `[9,44,-11] [25,61,7] [39,33,-4] [55,54,10] [71,37,-8] [88,57,4]`
  - Mobile: `[15,44,-9] [37,60,7] [61,35,-6] [84,55,9]`
- Card faces reuse the existing thumbnail path exactly as `CardTile` does:
  `thumbKey` (not full-res `imageKey`) rendered through `CardRotate`, with a
  `sizes` hint matched to the ~80px display and default lazy loading. This keeps
  the home page featherweight. Orientation is handled by `CardRotate`.

Both *which* cards appear and *where* they sit derive from the day seed, so the
whole showcase rotates together at 00:00 UTC.

## Data flow

Deterministic, server-resolved, mirroring the shipped `pickDailyExamples`
pattern (`web/src/lib/daily-examples.ts`) and the shared `mulberry32`
(`web/src/lib/random.ts`).

1. **Candidate query** — new `@revelio/db` query returning a **stable-ordered**
   (e.g. by `id`, never `random()`) pool of minimal card rows that have an
   uploaded image, carrying exactly the fields `CardTile`/`CardRotate` consume:
   `id`, locale `name`, `orientation`, `imageVersion`, `imageLang`,
   `defaultLanguage`. The card set (2001 WotC HP TCG) is small, so the pool is
   cheap — but because the home page is `force-dynamic` it must not re-query on
   every request: wrap the pool in a **day-keyed `unstable_cache`** so it
   resolves once per day. Selection is **locale-independent** (same cards
   worldwide); locale only affects the resolved name/image.
2. **Daily pick** — a `pickDailyCards(candidates, date, count)` helper shuffles
   the pool with `mulberry32(dayNumber)` and slices `count`, exactly like
   `pickDailyExamples`. Stable within a UTC day, rotates at 00:00 UTC.
3. **Server render** — `HomePage` (server component) resolves the daily set +
   `scatterPositions`, and **renders the cards already in their settled
   positions** in the server HTML. The showcase works with no JavaScript; the
   client component only *layers on* the one-time cast animation after
   hydration (no hidden-until-JS, no flash). 6 cards desktop, 4 on narrow
   viewports.

## Components

- **`getDailyShowcaseCandidates(db, locale)`** (new, `@revelio/db`) —
  stable-ordered pool of image-bearing card rows carrying the fields
  `CardRotate` needs (`id`, `name`, `orientation`, `imageVersion`, `imageLang`,
  `defaultLanguage`). Follows the shape of existing minimal-row queries
  (cf. `getRandomCardId`, `listCardsForSitemap`). Consumed through a day-keyed
  `unstable_cache` wrapper in the web layer.
- **`pickDailyCards(candidates, date, count)`** (new, `web/src/lib/`) — pure,
  deterministic selection helper. Unit-tested like `pickDailyExamples`.
- **`scatterPositions(date, count)`** (new, `web/src/lib/`) — pure helper that
  produces the per-cell jittered `[leftPct, topPct, rotDeg]` slots from
  `mulberry32(dayNumber)`. Computed on the server and passed to the component as
  props so SSR and client agree. Unit-tested for determinism, in-bounds output,
  and no horizontal-cell collisions.
- **`<CardConstellation cards positions />`** (new client component,
  `web/src/components/`) — renders each card as a locale-aware link (next-intl
  navigation) to `/card/[id]`, labelled by card name, faces via `CardRotate` +
  `thumbKey`, in a labelled `<section aria-label>` region. Cards are output in
  their settled positions (server-rendered); the component *adds* the one-time
  cast on mount, the rest-state drift, and the hover/focus reveal. Decorative
  stars/spark are `aria-hidden`. All motion gated behind
  `prefers-reduced-motion`; the cast fires **once per session**
  (`sessionStorage` flag) rather than on every navigation.
- **`page.tsx`** (modified) — fetch the daily set in the server `HomePage`, drop
  `<CardConstellation>` into the hero's lower band. Rotation logic parallels the
  existing example-chip wiring.

## Performance & progressive enhancement

The home page is currently featherweight; this feature must not regress that.

- **Thumbnails, lazy:** `thumbKey` images (not full-res), below the fold, lazy —
  never `priority`. `sizes` matched to the ~80px display.
- **No layout shift:** the band is fixed-height and cards are absolutely
  positioned, so nothing reflows as images load.
- **Compositor-only motion:** cast and drift animate `transform`/`opacity` only.
- **Cache the pool:** day-keyed `unstable_cache` means one candidate query per
  day, not per request, despite `force-dynamic`.
- **Works without JS:** cards are server-rendered in their final positions and
  are fully functional links before hydration; the client component only
  enhances them with motion.
- **Cast frequency:** the cast plays once per session (`sessionStorage`), so
  repeat navigations to home land on the calm rest state. *(Open decision —
  swap to every-visit if preferred.)*

## Accessibility

- Each card is a real link with an `aria-label` of the card name; keyboard focus
  gets the same visible reveal as hover.
- Stars and the wand-spark are `aria-hidden` decoration.
- The entire animation layer respects `prefers-reduced-motion: reduce`.

## Testing

- Unit-test `pickDailyCards` for determinism (same locale/day → same set),
  daily rotation (adjacent days differ), and `count` bounds — mirroring
  `daily-examples.test.ts`.
- Unit-test the new DB query against the standard Testcontainers Postgres
  harness: returns only image-bearing rows, minimal shape.
- Component render test for `<CardConstellation>`: renders N links to
  `/card/[id]` with correct labels; reduced-motion path renders without the
  cast.

## Rollout notes

- Purely additive to the home page; no schema change, no migration.
- `NEXT_PUBLIC_IMAGE_BASE_URL` is already required at build time and used
  elsewhere — no new env.
- No Meilisearch index change, so no ingest run required.
